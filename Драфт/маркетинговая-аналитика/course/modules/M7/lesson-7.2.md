# Урок 7.2 — ИИ-фабрика маркетинговой аналитики

**Цель урока:** по мотивам «AI-фабрики XTracker» (ИИ-конвейер разработки из 7 ролей) спроектировать аналогичную фабрику для аналитики: роли агентов от вопроса до отчёта, точки контроля человеком, оркестрация пайплайнов на n8n/Yandex Cloud; разобрать сценарий «исследование нового сегмента за один день».

**Перед уроком:** урок 7.1 (LLM-возможности и границы).

## Зачем это аналитику

Разовые запросы к LLM в чате — это ручной труд с непредсказуемым качеством. Фабрика — противоположность: **фиксированный конвейер ролей с контролем**, где каждый шаг воспроизводим, у каждой находки есть ссылка на источник, а человек стоит на контрольных точках, а не в каждом звене. XTracker так переупаковал разработку (постановка → безопасность → код → ревью → CI → приёмка); мы сделаем то же с аналитическим процессом — и заодно соберём это на доступных инструментах (n8n, Yandex Cloud).

## Теория

### 1. Референс: что делает XTracker (переносим принципы)

Из презентации «Фабрика поехала»: 7 ролей (бизнес-аналитик, системный аналитик, безопасник, AI-разработчик, ревьюер, CI-доктор, приёмщик); принципы: «задача входит — MR выходит»; **«ни одной улики без цитаты из источника»** (находка без подтверждения по точному пути/версии отбрасывается); регламентные прогоны вместо ручных проверок; человек открывает MR, автомерж выключен. Перенос в аналитику: у каждой цифры — запрос и версия данных; у каждого вывода — цитата респондента/источника; автогенерация отчёта без человека не публикуется.

### 2. Семь ролей фабрики маркетинг-аналитики

| # | Роль | Вход → Выход | Контроль |
|---|---|---|---|
| 1 | **Исследователь** (вопрос) | запрос бизнеса → постановка: метрика, сравнение, горизонт, решение | человек утверждает постановку |
| 2 | **Сборщик данных** | постановка → датасет (трекер, CRM, панели, парсинг) | проверки схем/свежести |
| 3 | **Разметчик** (LLM) | open-ends/отзывы → категории + confidence | слепая валидация κ (7.1) |
| 4 | **Синтетик** (LLM) | сегмент-описания → персоны, пилот анкеты | маркировка «синтетика» |
| 5 | **Модельер** | данные → расчёты/модели (когорты, LTV, DiD, атрибуция) | автотесты формул; peer-ревью методов |
| 6 | **Визуализатор/писатель** | результаты → черновик отчёта/дашборда | фактчек чисел и SQL человеком |
| 7 | **Ревьюер методологии** | черновик → вердикт: допущения, границы, что НЕ доказано | финальный человек-приёмщик |

Ключевая идея: не «один супермаркет-агент», а **узкие роли с интерфейсами** — так локализуются ошибки и возможен контроль.

### 3. Оркестрация: n8n и Yandex Cloud

Схема реального пайплайна «опрос → разметка → дашборд»:
1. **Яндекс Формы** (или Typeform) — сбор ответов;
2. **n8n** (webhook-оркестратор) или **Cloud Functions** — событие «новый ответ»;
3. **YandexGPT / GPT-классификатор** в контуре Yandex Cloud — разметка по кодбуку, выход JSON;
4. **Yandex Database / ClickHouse** — таблица результатов;
5. **DataLens** — дашборд; «Нейроаналитик» DataLens — вопросы поверх готовых датасетов.

Правила фабрики на любом стеке: промпты и кодбуки — в git (версионность); каждый запуск — лог (id ответа, версия промпта, результат); расхождения с ручной валидацией — метрика качества пайплайна на дашборде.

### 4. Что НЕ отдавать фабрике

Методология (выбор метода оценки, дизайн эксперимента), финальные выводы для бизнеса, коммуникация со стейкхолдерами, решения с деньгами. Всё остальное — кандидаты на автоматизацию с контролем.

## Разбор на данных

Сценарий «исследование нового сегмента (офисные заказы) за 1 день» на фабрике «ЕдаДома»: (9:00) исследователь формулирует постановку с человеком; (9:30) сборщик тянет открытые ответы из чата поддержки + отзывы + 50 интерьвью-заметок CRM; (10:30) разметчик категоризует барьеры (κ-валидация 12:00, 0,84); (11:00) синтетик генерит 6 персон офисных заказчиков и пилотирует анкету — 2 формулировки переписаны; (13:00) модельер: когорты офисных vs домашних, LTV-прогноз; (15:00) визуализатор собирает черновик отчёта с цитатами и SQL-ссылками; (16:00) ревьюер помечает «LTV-прогноз на 60-дневном окне — не доказано», приёмщик вырезает раздел; (17:00) отчёт ушёл с тремя проверенными выводами и одним явным «открытым вопросом». Без фабрики — две недели и то же «не доказано» вскользь.

## Подводные камни

1. **Фабрика без человека на контрольных точках** = конвейер по производству уверенных ошибок.
2. **Промпты в чатах, а не в git** — невоспроизводимость; «а как ты считал?» без ответа.
3. **Отчёт без «что НЕ доказано»** — главный дефект ИИ-черновиков: пишут гладко про всё; ревьюер обязан резать.
4. **Жёсткие цепочки**: пайплайн должен уметь останавливаться («данных мало — возвращаюсь к постановке»), иначе garbage-in-garbage-out с графикой.
5. **Стоимость и латентность**: не всякий шаг стоит агента; правило — автоматизируй частое и рутинное, редкое и сложное оставь людям.

## Домашнее задание

1. Спроектируйте фабрику для регулярной задачи «еженедельный отчёт по каналам»: какие роли, где человек?

<details>
<summary>Ответ</summary>

Сборщик (данные кабинетов+сквозная, автотесты схем) → модельер (CAC/LTV когорт по фиксированным формулам) → визуализатор (черновик отчёта) → ревьюер-автомат (проверка аномалий: SRM-подобные скачки, отсутствие данных) → человек: разбор аномалий и выводы. Исследователь и синтетик не нужны — задача рутинная; главное — версионированные формулы и алерты на качество данных.
</details>

2. Где в фабрике обязательна цитата к источнику (принцип XTracker)?

<details>
<summary>Ответ</summary>

Везде, где утверждение о факте: разметчик — ссылка на id ответа; модельер — запрос и версия таблицы; визуализатор — каждое число отчёта с источником; синтетик — пометка «сгенерировано». Находка без цитаты отбрасывается — иначе фабрика производит правдоподобные выдумки.
</details>

3. Почему «один суперсмарт-агент, который всё сделает» — плохая архитектура?

<details>
<summary>Ответ</summary>

Нет интерфейсов между шагами → ошибки не локализуются (не поймёшь, где соврали данные, модель или текст); нет точек контроля (проверить нельзя то, что не выделено); нет переиспользования ролей в других пайплайнах; промпт-инжиниринг «на всё» деградирует в усреднённое качество. Узкие роли с контрактами — управляемость.
</details>

## Шпаргалка

1. Фабрика = фиксированные роли с интерфейсами + контроль человека в точках, а не везде.
2. Семь ролей: исследователь → сборщик → разметчик → синтетик → модельер → визуализатор → ревьюер; приёмщик — человек.
3. Принципы XTracker: цитата к каждой находке; регламент вместо ручного; автогенерация не публикуется без приёмки.
4. Стек: Формы → n8n/Cloud Functions → YandexGPT (JSON) → таблица → DataLens; промпты в git, логи запусков, κ на дашборде.
5. Не отдавать: методологию, финальные выводы, решения с деньгами.
