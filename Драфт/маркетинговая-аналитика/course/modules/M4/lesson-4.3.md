# Урок 4.3 — ML/data-driven атрибуция: когда веса считает модель

**Цель урока:** понять, как машинное обучение переворачивает атрибуцию: веса не задаются правилом, а восстанавливаются из данных; что такое размеченные данные и откуда они берутся; как считается вклад касания; что умеет автоматическая (data-driven) атрибуция Директа/GA4 — и где границы доверия всем этим цифрам.

**Перед уроком:** уроки 4.1–4.2 (сквозная аналитика, правила атрибуции).

## Зачем это аналитику

Rule-based модели (4.2) делят ценность по правилу с потолка. ML-атрибуция обещает делёж **по фактическому влиянию касаний на вероятность конверсии**: учитывает все касания сразу, кросс-девайс, показы без клика и запоздалые покупки. Это ключевая тема по статье с vc.ru (обязательная в нашем курсе): она связывает UTM-дисциплину (3.2), сквозную аналитику (4.1) и будущий переход к инкрементальности (5.3).

## Теория

### 1. Размеченные данные — топливо модели

**Размеченные данные** — датасет, где каждому объекту приписана метка класса. В задаче атрибуции: **пользователь → конверсия (0/1)**. Собирается сшивкой всех систем (4.1):

- веб/моб-аналитика (Метрика, GA): переходы, поведение, устройства;
- рекламные кабинеты: показы и клики по кампаниям (включая показы **без клика** — view-through);
- **CRM — главный источник метки конверсии**: покупки/сделки мэтчатся с пользователями аналитики; кто не купил — класс 0.

То есть: «максимальный набор взаимодействий пользователя с брендом» + метка купил/не купил. Качество модели упирается в качество сшивки (рассинхрон систем, кросс-девайс) и в **дисциплину разметки** — UTM из урока 3.2 здесь буквально обучающие фичи.

### 2. Как модель считает вклад касания

1. Обучаем модель предсказывать **вероятность конверсии** по цепочке касаний и поведению: фичи — каналы/кампании касаний, время и устройство, поведение на сайте; алгоритмы — логрегрессия (интерпретируемая база), случайный лес, градиентный бустинг (CatBoost/LightGBM).
2. **Вклад касания = разница прогнозов**: вероятность с этим касанием минус вероятность без него (убрали из цепочки — пересчитали). Это uplift-логика: касание «полезно», если поднимает предсказанную вероятность.
3. Ценность конверсии распределяется **пропорционально вкладам**; можно оценивать и группы кампаний (брендовые vs небрендовые — выявление перехвата).

Пример из статьи: перераспределение конверсий с бренд-кампаний на небрендовые → корректировка ставок → **заметный рост клиентов при том же бюджете**. Это и есть практический продукт ML-атрибуции — не «красивые веса», а другие ставки.

### 3. Что модель чинит по сравнению с правилами

| Проблема last-click | Как обходит ML-модель |
|---|---|
| кросс-девайс | сшитые профили (4.1) + устройство как фича |
| view-through (показ без клика) | показы — полноценные касания-фичи |
| запоздалая конверсия | вся история касаний с временами |
| перехват бренд-кампаниями | вклад «с/без» обнуляет мнимый вклад перехватчика |
| веса с потолка | веса = измеренное влияние на вероятность |

### 4. «Из коробки»: data-driven атрибуция платформ

- **Яндекс Директ**: автоматическая атрибуция — ML-модель сравнивает конверсионные и неконверсионные цепочки касаний (окно до 180 дней); влияет на обучение стратегий биддинга.
- **GA4**: data-driven по умолчанию.
- Ограничение принципа: платформа видит только **свои** касания — внутри ecosystems, не весь портфель.
- Своими руками: Марков-цепи и значения Шепли на полных путях (open-source: ChannelAttribution, DP6 Marketing-Attribution-Models); вход — сырые пути из Logs API Метрики/BigQuery.

### 5. Границы доверия (главный слайд)

- ML-атрибуция **корреляционна по природе**: модель улавливает «касание сопутствует конверсии», но селекция («качественнее аудитория пришла») не отделена от влияния («касание CAUSED конверсию»).
- Вопрос «что станет с выручкой, если отключить канал» атрибуция не отвечает — только **эксперимент** (гео-тесты 3.3, incrementality 5.3; у Купера прямо: «модели ML не умеют отвечать на вопрос what-if»).
- Валидация: где эксперименты были — проверять модель по ним; где не были — помнить, что это модель, а не измерение.

## Разбор на данных

Учебная мини-модель на цепочках «ЕдаДома» (логрегрессия, фичи — касания каналов): предсказанная P(конверсия). Для пользователя с цепочкой «медийка → контекст → бренд»: P = 0,081; без бренд-касания P = 0,078 (вклад ≈ 0,003 — бренд почти ничего не добавляет, он «перехватчик»); без медийки P = 0,049 (вклад 0,032 — медийка подняла вероятность в разы). Против last-click: бренд получил бы всю конверсию, медийка — ноль. Пересчитав все цепочки: медийка +19 п.п. доли против last-click, бренд −18 п.п. Ставки на небренд-контекст подняли — при том же бюджете +6% клиентов (паттерн кейса из статьи). Но: прежде чем резать бренд-кампании — гео-тест (5.3): модель видит корреляцию, а инкрементальность проверяет огонь.

## Подводные камни

1. **Мусор на входе**: опечатки UTM (3.2) и рваная сшивка (4.1) → модель учит шум; качество разметки = качество атрибуции.
2. **Метка конверсии из CRM с опозданием/неполнотой**: модель учится на «не купивших пока»; держите horizon обучения.
3. **Селекция аудиторий** неотличима от влияния касаний внутри модели — не обещайте бизнесу каузальность.
4. **Переобучение на популярных каналах**: цепочек с медийкой мало — вклад занижен; следите за покрытием фич.
5. **Смена модели биддинга при переходе на DDA** меняет закупку — разделяйте эффект «модель атрибуции» и «новая стратегия».

## Шпаргалка

1. ML-атрибуция: P(конверсия|цепочка) обучается на размеченных данных (метка — из CRM); вклад касания = ΔP «с/без».
2. Чинит: кросс-девайс, view-through, запоздалые конверсии, перехват брендом; веса — из данных, не с потолка.
3. Практический продукт — другие ставки: перераспределение на истинные драйверы (кейс: рост клиентов при том же бюджете).
4. Из коробки: DDA Директа/GA4 — внутри своей экосистемы; своё — Шепли/Марков на полных путях.
5. Граница: корреляция ≠ причинность; «что, если отключить» — только эксперименты (5.3).
